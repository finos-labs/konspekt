# Noteworthy: the fleet role skills kept the legacy `--root` attach after the config-driven cut

The fleet CLI attaches to a fleet in one of two ways (`cli.mjs` `attach()`):
`--canonical <path>` reads the committed `.konspekt/fleet/config/fleet.json` and
resolves outbox worktrees from `git worktree list` (`loadFromConfig`), while
`--root <dir>` is the legacy flat path that reads `<dir>/fleet.json`
(`loadFleet`). Config-driven setup (`setupFromConfig`) never writes a `fleet.json`
manifest at the root — paths are derived at attach time — so on a config-driven
fleet `--root <fleet folder>` hits a missing `fleet.json` and fails with a
file-not-found (ENOENT), while `--canonical` works. This is the model shift
recorded in [[task-fleet-config-driven-setup]] and [[nw-fleet-config-on-canonical]].

The role skills lagged that shift. `fleet-proposer-common` (step 6, `propose`)
and `fleet-committer` (the Pass steps: `run-pass`, `rebuild-index`, `bless`) kept
the legacy `--root "FLEET_ROOT"` invocation, so a proposer or committer run
against a config-driven fleet (the current model, and how the collateral/CDM
fleet is stood up) gets the ENOENT. The committer skill was internally
inconsistent: its "Switching the canonical branch" section already used
`--canonical "<canonical>" --instance-subdir .konspekt/instance`, which is the
correct current form. Observed 2026-10-24 by a collateral-fleet spec-writer
proposer, which correctly declined to patch core text from inside the
spec-writer role and reported it up.

The constraint: a fleet role skill invokes the config-driven `--canonical`
attach (proposer: `--canonical "CANONICAL"`; committer: `--canonical
"FLEET_ROOT/canonical" --instance-subdir .konspekt/instance`), not the legacy
`--root`. The neutral sources under `.konspekt/agents/skills/` are the single
source of truth; the `.claude/skills/` mirror is regenerated by
`tools/sync-agents.mjs`. Distinct from [[nw-fleet-proposer-skill-drift]], which
is about a proposer loading a stale skill from its own outbox branch rather than
canonical — this is a defect in the canonical text itself.
