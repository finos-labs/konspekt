# Task: Generate ROADMAP.md as a graph projection with a conformance freshness gate

Emit `ROADMAP.md` from the instance graph — goals under a now / next / later
horizon, each with its `decomposes` tasks — reusing `loadInstance()` from
`lib/conformance.mjs` and patterned on the pure, deterministic
`visual/build/snapshot.mjs` (AUTOGENERATED banner, no wall-clock, content
identical on re-run over an unchanged instance). The graph remains the source of
truth; the markdown is a projection for readers who do not yet know konspekt.

Add a conformance freshness gate that regenerates `ROADMAP.md` and diffs it
against the committed copy, failing validation when the two differ. No existing
gate does this — conformance validates only the graph and provenance hashes — so
this is new work. It requires no workflow write permission, because the check
only reads and regenerates.

The generator is run manually by whoever accepts a graph change (optionally
eased by an npm script or pre-commit hook); the freshness gate is what makes
regeneration reliable rather than a matter of discipline. Automating the trigger
is deferred to [[task-roadmap-generation-workflow]].

Success: a committed `ROADMAP.md` a reader unfamiliar with konspekt can follow,
and a failing conformance check whenever it drifts from the graph.
