Denis: How does cursor multi-agent setup work? The one that runs outside of IDE

Claude: Cursor's out-of-IDE multi-agent feature is background agents (also called cloud agents). ... Each agent runs asynchronously on a Cursor-hosted cloud VM, separate from your local editor. ... The agent clones the repo (needs GitHub read-write), works on its own branch, and auto-pushes commits. You review and merge through a pull request, or take over the machine directly mid-run. ... Multiple agents run at once, each on an independent branch in the same repo. ... Cursor is one branch and one PR per agent — the "independent-branch integration" model. Your fleet rejected that for a single serialized committer: agents never write canonical, they propose, and one committer folds proposals. ... Cursor's human gate is GitHub PR review — the thing konspekt deliberately demotes.

Claude: Yes — that layering is sound ... The PR carries the code diff; the konspekt proposals carry the project-state graph (the decisions, findings, artifacts, and provenance behind that diff).
