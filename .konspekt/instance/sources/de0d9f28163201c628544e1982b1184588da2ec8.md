# Source excerpt — "atom" vocabulary (konspekt spec)

elisions marked `[…]`. Selected, never paraphrased.

**Human:** would "nodes" be more accurate? Atom isn't really a first class noun in the data model

**Assistant:** No, "nodes" would narrow it wrongly. In this instance `nodes/` is one directory holding goals, investigations and tasks, and the edge table addresses things as `node:`, `concept:`, `noteworthy:`, `artifact:` and `waypoint:`. A feed of the last ten changed things has to include concepts and noteworthy items, which are not nodes. […] You are right that "atom" is not a defined type. It runs all through the spec as a working word — a proposed atom carrying confidence, an extracted atom classified as new, duplicate, update or conflict, a summarized excerpt being an atom in disguise — but it names no schema construct. The word that does is "entity". The serialization spec talks about an entity's provenance, says source excerpts are not graph entities, and the reconciliation spec describes resolving an atom to an existing entity, which puts the two side by side with "entity" carrying the formal weight. […] Worth noticing that the atom-versus-entity duality is an unreconciled bit of vocabulary in the spec itself, sitting next to the naming question already flagged between the two reconciliation documents.

**Human:** ok, let's go with "entity"

**Human:** add a task to add "atom" to the usability goal. commit and push, no PR. then we need to talk about push mechanism
