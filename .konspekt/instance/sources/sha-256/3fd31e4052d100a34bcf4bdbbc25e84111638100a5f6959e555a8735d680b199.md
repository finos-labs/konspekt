**Claude (proposal, `nw-landed-commit-recorded`):** the review-unit log mostly works under squash and rebase already, because GitHub keeps a pull request's original branch commits. The binding audit breaks: it requires every non-merge default-branch commit to be named in `changed.md`, and a squash commit or rebased commits have new SHAs. Add a `landed` column to `review-units.md`: the default-branch commit that carries each bound commit's change — the commit itself (merge commit or direct), the squash commit, or the rebased commit matched by `git patch-id`. The binding audit counts a default-branch commit as bound when `changed.md` names it or it is the `landed` of a row whose commit is bound. Replaces the spec's "squash and rebase are out of scope". Implemented as `task-review-unit-landed-commits`, in the same pull request as `task-review-unit-direct-rows`.

3. Rewriting before merge (force-push) can leave a bound SHA nowhere: a warning, or rewrite the binding rows?
4. Rebase matching: when `git patch-id` finds no match, fall back to position and mark the row?
