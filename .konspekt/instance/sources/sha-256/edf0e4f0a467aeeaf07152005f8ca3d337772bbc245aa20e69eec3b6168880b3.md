> `tools/review-units.mjs` reads the forge only through `gh api graphql` and `gh repo view`, which also uses GraphQL. A session whose GitHub access is REST-only cannot run it. Claude Code cloud sessions are one example; on 2026-11-22 a deck-refresh session needed a wrapper to regenerate the log. The fix has five parts:
>
> - **Option.** Add `--api auto|graphql|rest`. The default is `auto`: use GraphQL, and fall back to REST when the GraphQL call fails.
> - **REST path.**
>   - List pull requests from `GET repos/{repo}/pulls?state=all&sort=created&direction=asc` (paginated).
>   - Map each one to the same unit shape. `merged_at` set means `merged`. `merge_commit_sha` is kept only when merged. The timestamp is `merged_at`, else `closed_at`, else `created_at`.
>   - Read each pull request's commits from `GET repos/{repo}/pulls/{n}/commits`. This costs one call per pull request.
> - **No other GraphQL dependency.**
>   - The default branch comes from `gh api repos/{repo} -q .default_branch`.
>   - When `--repo` is omitted, the repository comes from the `origin` remote URL.
> - **Test.** A pure `restUnit(pr, commits)` mapping, tested in `test/review-units.test.mjs`, including an open pull request and a closed, unmerged one.
> - **Acceptance.** On konspekt, `--api rest` and `--api graphql` produce identical logs.
>
> The conformance component ships the tool, so cdm-collateral picks up the change at its next kit refresh.
