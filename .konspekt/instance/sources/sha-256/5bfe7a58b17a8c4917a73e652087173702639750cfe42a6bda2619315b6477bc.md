**Why the two checks failed:**
- This clone has `core.autocrlf=true`, and `.gitattributes` had no rule for `setup/templates/`. `git ls-files --eol` showed all 12 templates checked out with CRLF.
- `setup/init.mjs` copies the templates byte for byte, so the scaffolded `project.md` had `binding: required\r`.
- The test removes the `binding:` and `basis:` lines with `/^binding:.*\n/m`. In JS, `.` does not match `\r`, so nothing was removed and `init.mjs --check` saw no missing fields.
- The same CRLF bytes also break the rule that `.gitattributes` already sets for `.konspekt/instance/**/*.md`, because the checker hashes raw bytes. So a scaffold run from a Windows checkout wrote CRLF instance markdown into the adopter's repository.

**Fix:** I added `/setup/templates/** text eol=lf` to `.gitattributes`, with a comment in the style of the existing rules, and re-checked-out the templates. All 12 now show `w/lf`. I left the test regex strict, so the test will fail again if CRLF comes back.
