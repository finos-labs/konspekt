# Source excerpt — CAS/cursor concurrency seam (C1 local, C2 via datastore at scale)

Verbatim, 2026-09-20.

---

**Human (context):** the CAS/cursor concurrency work is the prerequisite that isn't started

**Human:** for non-enterprise (single human, N agents) C1 is fine. At scale, this has to become C2 and will most likely be solved by an underlying datastore

---

C1 = the R/W API row-merges the single `edges.md` (union by edge id; only same-edge
edits reject to a human). C2 = per-atom addressability so ordinary compare-and-swap
suffices — at enterprise scale delivered by a datastore's native per-row CAS, not by
hand-sharding git files. The versioned read/write contract and the opaque
changes-since cursor are the backend-neutral seam both share.
