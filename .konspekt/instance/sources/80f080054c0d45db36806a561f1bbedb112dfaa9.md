**Human:** neither option. I think that in engineering mode most, if not all, LLM-executed commands must be recorded. The questions are 1. what to link them to and 2. where to store. I think the answers, then, are: 1. any LLM-executed script executed in the conversation context about any entity type and 2. your option C: /commands/executed.md, and in it - entity id | command table; one to many, ordered by execution timestamp (natural execution order).

**Assistant:** Storage: commands/executed.md — a table | entity | command |, one entity to many commands, append-only, row order = execution order (the natural order is the timeline; no stored timestamp needed, which dissolves the v1 timestamp-serialization problem). The command column is the content hash referencing commands/<hash>.md, and executed stops being a core edge-table kind.
