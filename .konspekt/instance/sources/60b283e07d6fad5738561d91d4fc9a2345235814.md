**User:** re: #1 - can't that be derived from sources? source spec is git agnostic and has timestamps, doesn't it

**Claude:** "Half of it can. The timestamp you mean is `provenance.timestamp`, which sits on the entity, is storage-agnostic, and records when the source exchange happened. That gives the proposal side of the interval with no git involved. The source file itself carries no structured timestamp, only a prose header.

The acceptance side has no record in the model. `provenance` points at the exchange the atom was extracted from. When a human accepts later, the flip rewrites `review` in place and nothing points at the accepting exchange, so there is no second timestamp to subtract from. […]"

**User:** I think I confused the timestamp (created at, updated at) on the nodes.  But wouldn't updatedAt and review: accepted effectively tell us when am atom became accepted? Or should we introduce status change timestamp?

**Claude:** "`updatedAt` plus `review: accepted` gives the last time the atom was touched, which equals the acceptance time only if acceptance was the last edit and the flip actually bumped the field. The instance fails both conditions: […]

So `updatedAt` cannot carry this, and a dedicated timestamp is the right move. […]

1. **Scope of the timestamp.** Options:
   - `reviewedAt` only, on every entity. Smallest change and answers acceptance latency. This is my lean for a first step.
   - `reviewedAt` plus `statusChangedAt`. Covers cycle time as well, but each field holds only the latest transition, so a task that went open, active, resolved keeps one of the two intervals.
   - An append-only transition log (`entity | field | from | to | timestamp | sourceRef`), in the style of `commands/executed.md`. Keeps full history, covers edges by id, and gives `task-signed-accepts` an event to attach a signature to. The cost is a second place where state is written, so it needs a conformance check that the last log row matches the entity's current value.
2. **Edges.** The edge table has no per-row timestamp. A `reviewedAt` field means a new column; the log option covers edges with no table change.
3. **Atoms accepted at birth.** Decide whether `reviewedAt` is required on them (equal to `createdAt`) or optional and read as `createdAt` when absent. My lean is required, so the projection never has to infer.
4. **Backfill.** Git history holds the real flip times for the 32 late-accepted entities. Decide whether to backfill or start from the change forward."
