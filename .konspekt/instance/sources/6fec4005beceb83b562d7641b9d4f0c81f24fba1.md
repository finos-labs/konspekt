## Thread A -- validation experiment (elided lead-in)

### human
the cleanest experiment is a human working on a project with konspekt enabled
vs. a human working on a project without konspekt. We might need to make
assumptions that describe the process, e.g., one new conversation a day, certain
number of decisions, certain number of to-dos, certain number of mental notes.
Come up with N well known project/problems. Simulate human prompts. I mean this
is a non-trivial test

### assistant
[...] The one thing that must be identical across arms is the work itself -- same
project, same sequence of decisions and to-dos, same order. The only difference
is whether konspekt is in the loop. [Simulated prompts are] where the experiment
is most likely to break. [Options: scripted prompts; blinded human-driver;
LLM-simulated human.] The credibility problem across all three: who or what
stands in for the human's own memory in arm B? [Recommends a single clean pilot
first.] [...]

### human
should this really be done in a classic medical trial fashion? two groups, one
with placebo (no konspekt) one with the actual pill (with konspekt) over the
same *type* of problems over long enough period of time

### assistant
[...] The drug-trial analogy breaks in three specific places: you can't blind the
participant; "same type of problem" carries far more variance than "same
condition"; the outcome isn't a scalar. The standard move when N is small and
between-person variance is large is the within-subject crossover: each
participant does both arms, order randomized, and is their own control. My lean
is crossover for this effect size and realistic N. Run the scripted pilot first
(cheap), then the crossover trial (credible). [...]

## Thread B -- conversation binding

### human
have they produced any konspekt artifacts?

### assistant
No -- nothing in either conversation produced a konspekt artifact. [Neither
session wrote into a konspekt instance; the deck was a plain file.] This
experiment-design conversation is close to a worked example of what konspekt is
supposed to catch [...] Instead it lives only in this chat transcript, which is
exactly the kind of context that goes missing next week.

### human
I think we need to have a change in skills, to where in a Konspekt enabled
project all conversations must be conducted within a graph entity. The LLM must
proactively and unconditionally request this from human

### assistant
The reason is structural. Today konspekt captures a conversation from outside,
after it happens, if anyone remembers. Nothing binds the conversation to the
graph while it's live [so the default is no capture]. Your fix inverts the
default -- binding becomes a precondition while the conversation is happening.
[Three wrinkles: cold start; one conversation crosses several entities;
"unconditionally" works against the friction goal. Underneath: soft skill-nudge
vs hard persist-time gate.] [...]

created and if so - of what type.
