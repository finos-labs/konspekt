A fleet proposer has no protocol path for a repository file outside the konspekt
instance. The committer moves exactly one proposal directory from an outbox to
canonical (`proposals/<id>/` with `entity.md`, `source.md`, `edges.md`,
`meta.json`); `run-pass` writes only under the instance directory, and `bless`
is field-only and authors no content. Consequence: every file a proposer writes
— documents, source code, tests, configuration — and the changed-code rows that
bind code stay on the outbox branch and never reach canonical.

Observed 2026-10-24 in cdm-collateral-fleet (spec-writer outbox, constraint
`nw-fleet-no-file-path`): `artifact-business-case` was folded and blessed on
`e2e-wiring` with `location: docs/analysis/business-case.md`, while the document
itself and its changed-code row never reached canonical — so canonical holds an
accepted artifact whose `location` does not exist. The only route today is a
manual human merge or cherry-pick of the outbox branch, outside the fleet.

Three candidate fixes for the konspekt core to decide: (1) the proposal carries a
verified file set written beside the atom in the same fold commit, with its
changed-code rows; (2) the proposal names outbox commits the committer verifies
touch only declared paths and applies deterministically at fold; (3) the spec
states that only atoms fold and repository files reach canonical by human merge,
with the artifact `location` checked at bless time.
