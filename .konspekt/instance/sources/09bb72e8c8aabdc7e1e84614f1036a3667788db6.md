The committer folds onto the canonical worktree's CURRENT branch, not the
configured canonicalBranch. commitAll(canonicalPath, ...) commits in the
canonical worktree without checking out any branch; canonicalBranch in
.konspekt/fleet/config/fleet.json is used only by setup (to fork the outbox
branches) and as attach/doctor metadata (loadFromConfig takes cfg.canonicalBranch
|| currentBranch(canonicalPath)). So the two can silently disagree: switch the
worktree's branch without updating the config and folds go to the new branch
while doctor/logs still report the old one; update the config without switching
the worktree and setup forks outbox branches off a branch the committer is not
actually writing.

Switching the canonical branch therefore has to move three things together:
(1) check out the new branch in the canonical worktree (what actually redirects
the fold target); (2) set canonicalBranch in the config to match; (3) refresh
each proposer outbox branch onto the new canonical by merging it in, so the
proposer authors against the new graph (binding resolves) and loads current
skills. teardown + re-setup does not achieve (3): setup creates outbox branches
with newBranch and fails on an existing one, and deleting the branch first drops
un-folded proposals. The proposer handle and its outbox branch name are keyed to
the handle, not the canonical branch, so they do not change.

Proposed hardening: run-pass and doctor should assert the canonical worktree is
checked out on the configured canonicalBranch and refuse on mismatch, turning the
silent disagreement into a loud one.
