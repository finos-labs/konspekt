**User:** I installed konspekt into cdm-collateral [...]. Should the lib and the spec directories be outside of konspekt? [...] Now the question is whether lib and spec are supposed to be under root or not. What does Konspekt's own setup script do? what does the manual install guide say?

**Claude:** "The setup script (`init.mjs`). The base scaffold writes only the `.konspekt/` umbrella — `instance/`, `OPERATING.md`, `NOTES.md` — plus the agent files. It contains no `lib/` or `spec/` literal anywhere. `--persona engineer` writes one thing: the `personas: [engineer]` line into `project.md` [...]. It vendors no persona code. The only thing that adds `lib/` is the `conformance` component, whose manifest targets `to: lib/conformance.mjs` and `to: lib/validate.mjs` — repo root, by design. [...] No component writes `spec/`, and there is no persona component. [...] `validate.mjs` statically imports `./load-personas.mjs`, and `conformance.mjs` statically imports `./authority.mjs`. The `conformance` manifest ships neither. I confirmed the component is non-runnable as declared — installing only its two files and running the checker crashes on the first import: `Error [ERR_MODULE_NOT_FOUND]: Cannot find module '…/lib/load-personas.mjs' imported from …/lib/validate.mjs`. [...] to make the checker run against your `personas: [engineer]` instance, someone copied in `load-personas.mjs` and `authority.mjs`, and then `load-personas` resolves the persona registry at `lib/../spec/personas/engineer/registry.mjs` — which is what created a root-level `spec/` in your repo. That `spec/` is a side effect of patching the component [...]."

**User:** yes - draft and persist, and I think we need to update the docs and the installer?
