The problem

Using Gen AI on
complex projects is tricky

Gen AI

Moves fast, generates a lot of output, starts threads, maintains its own context, and can be hard to control.

so the project starts to slip —

  • losing track of the goals and outcomes
  • losing track of to‑dos
  • forgetting which decisions were made
  • not keeping notes of ideas and thoughts
The human

Works slower, generates less output, and manages their own context by hand.

They carry the project across memory, local notes, and scattered chat history — and can’t keep track of everything the model produces.

One produces more than can be tracked; the other can’t keep up — and the combination creates a lot of friction.

The solution

This is how konspekt helps

The graph

konspekt manages project context as a graph of goals, tasks, decisions, and notes. You drive it from the familiar chat interface, and control verbs keep you in the driving seat.

typed model · control verbs
Record keeping

konspekt keeps an immutable, auditable ledger of project activity — from the verbatim record of who proposed what, to the decisions made, and finally the commands run and files changed.

Provenance is kept for every entry: the exchange it came from, the model that proposed it, and the maintainer who accepted it.

The source is stored as direct quotes, both sides of the exchange word for word, rather than a summary of it.

Each source is addressed by a hash of its bytes, and every entity carries that hash, so an altered quote no longer resolves.

Provenance

Three content‑addressed channels

An action journal and decision-making trail: who did what, when and how — and who accepted each proposal.

Each channel stores its text under a filename that is the hash of that text. An entry verifies when hashing the file again returns the hash it was stored under, so an altered record stops resolving.

sources/<hash>.md

Verbatim excerpts

The text an entry was drawn from, covering every participating turn — human prompts and assistant responses, copied as written. Selecting which spans to include is allowed; rewriting or summarizing a span is not.

commands/<hash>.md

Executed commands

The verbatim text of each command run while building, one file per command. A separate log binds each run to the entity it was about, in execution order. Output is not stored: the record answers what was run.

changes/changed.md

Changed code

A row per entity, commit, and file, in commit order. The change itself stays in version control and is reached through the commit token, so only which files changed, and for which entity, is kept here.

The advantage compounds

Hypothesis
Holds
when
Across sessions — within a single conversation, native context is cheaper.
Memory accretes ungated — no human curation, no supersession.
The work has real structure — interdependent decisions, provenance, things that supersede.

Given these hold, a curated, fit‑for‑project structure turns recall into deterministic traversal — following typed edges to what’s related, instead of re‑deriving it or ranking by similarity.

Size — the graph grows only as the human accepts entries; native memory accretes on its own. The larger the project, the wider the size gap.
Accuracy — traversal reaches the related entries by construction; similarity retrieval guesses and drops the connective tissue. More edges, more that only structure recovers.
Integrity — curation and explicit supersession keep the record correct; uncurated memory drifts and corrupts. The longer it runs, the more drift the graph avoids.

Directional. The gap comes from an A/B — the same work run with and without konspekt, measuring what it takes to restore and hold fidelity.

Invariants

Principles the design holds to

I

The store stays simple

The backing store reads and writes. Judging a proposal happens in the review conversation, not in the storage layer.

II

The read path is neutral

An instance is plain files that anyone can re‑read without an API, so adopting konspekt does not commit a project to one tool.

III

Distribution is a projection

Anything published is regenerated from the graph, so no second copy exists that can drift away from the record.

IV

Merge converges, accept does not

Anyone may propose, and proposals merge without conflict. Deciding what is accepted stays with a named authority.

V

Provenance completeness

Every atom binds — to its source and to an entity. A conversation resolves to the graph or is recorded as a deliberate non‑binding; none goes silent.

Questions we hear

FAQ
Why not the model’s built-in memory?
Native memory re-derives context, and the cost grows super-linearly with complexity. konspekt keeps a typed, verifiable record whose cost stays flat — and it’s portable across vendors.
Why not a wiki or a doc?
A doc drifts from what actually happened. konspekt’s entries are content-addressed with verbatim provenance, so the record can’t silently diverge — and each one is accepted by a named maintainer.
Why not Jira or a tracker?
Those track human-assigned work. konspekt tracks the AI-driven work and its decisions, read and written by the agent in the loop. It runs alongside your tools, not instead of them.
Does it lock me in?
No. An instance is plain files with a neutral, non-API read path, Apache-2.0 on GitHub. git is the reference store; MongoDB and Postgres sit behind the same interface.
