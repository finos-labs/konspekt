Collaboration

goal-collaboration

Work a project as a team, people and agents together, without weakening the propose→accept rule.

task
Multi-author review
Several people propose on one project. Who can accept is named in the project config, so authority stays put when the host changes.
task
Agent fleet
One reviewer over many proposing agents, each proposal tagged with the model that produced it.

Observability

goal-observability

See the state and history of a project through queries over the graph, run as projections that add nothing back.

task
Graph analytics
Measure the record: how connected it is, how deep its sources run, how many proposals never landed.
task
Real-time monitoring
Watch decisions change as they happen, a standing view rather than an on-demand report.

Portability

goal-portability

Move between tools without lock-in. The record is the same wherever it lives.

task
Enterprise persistence
Run on a database or object store instead of git, behind one storage interface, with identical content addresses so migration is a re-hash check.

Accountability

goal-accountability

Answer who is responsible. The law decides responsibility; konspekt makes the underlying facts answerable with evidence.

task
Responsibility report
For any accepted decision, the full chain: what was proposed, by which AI, who accepted, and when.
task
Signed accepts
Optionally require a maintainer's acceptance to be signed. Off by default, on where the legally-bound role is assigned.
task
Protected role change
Changing who carries legal weight is the most guarded action, gated by the bound maintainers themselves.
Boundary. konspekt records what a handle did, unaltered. Tying a handle to a real person, and any AI output that never enters the graph, are out of scope, with the signing key named as the plug-in point.
Concurrency & controlruns under every goal above
  • Sharded edge table. Edges shard by their owning node, so independent proposals never collide; a rebase-append retry covers the rare overlap.
  • One primitive, two uses. Stage objects, then swap a single pointer. The same commit mechanism gives object-store atomicity and multi-writer safety.
  • Propose, never accept. Any number of agents can propose at once; only a named maintainer accepts, so the responsible position is always human.
  • Whole-table checks move out. When no writer sees the full table, duplicate and dangling-edge checks run in the conformance checker, keeping the store dumb.
