konspekt · dual-commit-channel fleet

A fleet with two commit channels

When the fleet runs on a runtime whose agents also produce code — Cursor background agents are one instance — each ordinary agent commits to two channels: code to its own branch for a pull request, and a konspekt proposal to the committer. The committer's scope does not change: it writes canonical graph state only.

What changes, and what doesn't

Against the general fleet, the committer side is unchanged: one serialized writer, canonical graph only, human-accepted proposals. What widens is the ordinary agent's scope — it now commits and pushes code to its own branch for a pull request, a second integration path running alongside the proposal path.

This is why the two outputs stay separated: code on the PR branch, the proposal off it (a separate outbox ref or MCP only). Cursor background agents are one instantiation of this dual-channel shape; any runtime whose fleet agents also produce code fits the same picture.
