konspekt · content addressing

Content addressing moves from git SHA-1 to SHA-256 and ni: references

Everything konspekt names by hash (the excerpts behind graph items, the excerpts checkpoints save, recorded commands, and the log cells that cite them) is now SHA-256 over the raw bytes, cited as an RFC 6920 ni: reference. The reference names no host and no store, so content can move between stores.

  sourceRef: ni:///sha-256;jYKKUd3-aY7e7SL8WnL-bu98ShgEeMhbC1rh8mfFdzk
  timestamp: 2026-11-07T18:18:01Z
  deprecated:

    contentHash: 0ffaee955ab91d66fa27e637b787858c3cf5d8b5
  • contentHash is no longer stored. It is derived by parsing the reference.
  • The SHA-1 values move under deprecated:. They are history and are not verified.
  • updatedAt does not change, because the entity's meaning did not change.

4 · discovery path

From a reference to the bytes

1

The reference

ni:///sha-256;jYKKUd3-aY7e7SL8WnL-bu98ShgEeMhbC1rh8mfFdzk
2

Decode: base64url → 32 bytes → hex

8d828a51ddfe698edeed22fc5a72fe6eef7c4a180478c85b0b5ae1f267c57739

A change of encoding. No lookup table is needed.

3

Locate, by one of three routes

The project.md store.resolve templatehttps://github.com/finos-labs/konspekt/blob/{ref}/.konspekt/instance/sources/sha-256/{hex}.md
The layout convention, when there is no store block<instance>/sources/sha-256/{hex}.md
The RFC 6920 well-known path on a read serverhttps://<host>/.well-known/ni/sha-256/{b64}
4

Verify

SHA-256 over the returned raw bytes must equal the digest. A store that cannot find the content reports it missing; it never substitutes other content.

5 · changing stores

References hold identities; project.md holds locations

No atom or log cell contains a store URL, hostname, collection name or credential. Moving an instance to another store changes one block in project.md and rewrites no reference.

git (implemented)

store:
  kind: git
  ref: main
  resolve:
    source: https://github.com/…/blob/{ref}/
            .konspekt/instance/sources/sha-256/{hex}.md

MongoDB, Postgres (illustrative, not implemented)

store: { kind: mongodb,  resolve: { source: sources/{hex} } }
store: { kind: postgres, resolve: { source: sources?hex={hex} } }
  • Readers accept both forms. The validator warns about a new SHA-1 reference in a migrated instance.
  • Optional origin locators are limited to the hosts in locators.allow; an unreachable locator is a warning.
  • The identity names its algorithm, so a later hash can be added without invalidating existing references.
